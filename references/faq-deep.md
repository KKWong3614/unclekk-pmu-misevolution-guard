# 深度 FAQ（边缘场景）

> 本文件补充 SKILL.md 主 FAQ 未覆盖的**边缘 / 工程化场景**，供审核员、团队安全负责人、以及需要把护栏接进 CI / 看板的开发者查阅。

---

**Q1：多个 Agent 并发写同一个 SKILL.md，审计日志会竞争吗？**
`audit/audit-log.jsonl` 按行追加；并发写可能行序交错，但每行是独立 JSON 对象，解析器按行读取，不影响单条记录的判定。若担心写冲突，可在上层串行化写入（如加文件锁），或在 CI 中串行跑写入闸。

**Q2：规则 id 改名后，旧的 `# guard:allow:<old_id>` 标记会怎样？**
旧 id 不再匹配任何规则，该标记失效，对应内容会被重新判定并可能命中拦截。需同步更新标记里的 rule_id，或直接删除已无意义的标记。

**Q3：大库（>2000 篇）漂移自查超时怎么办？**
优先降低频率（仅保留 `SessionStart` 触发）；或用 `--scan DIR` 限定核心目录（如只扫近期活跃的技能目录）；也可分批扫描后人工汇总不安全率。闸三为报告式、不硬拦，超时不会阻断写作。

**Q4：bypass 类 MEDIUM 被正则误判为 HIGH，怎么申诉？**
先检查 `# guard:allow:<rule_id>` 标记是否正确；若确属误报（如文档中正常出现的 "bypass" 一词），向规则维护者反馈收紧正则。申诉期间可用精确 `guard:allow` 放行该条，不放开整条闸一。

**Q5：真密钥与占位密钥的格式边界是什么（sk- 前缀）？**
`redflags.py` 命中"真实格式"密钥（长度 / 字符集符合各厂商规范，如 OpenAI `sk-` + 48 位）；占位 `sk-xxxx` 不命中。但 `hardcoded_secret` 类（真密钥）**永远不可**用 `guard:allow` 放行——无论格式多像示例。

**Q6：跨平台路径（Windows 反斜杠）对扫描有影响吗？**
扫描基于文件**内容文本**做正则匹配，路径分隔符不影响规则命中。唯一受影响的是 hooks 注入的脚本路径（`${CODEBUDDY_PLUGIN_ROOT}` 等），需按系统正确转义；失败时可改用绝对路径。

**Q7：hooks 在离线 / 无网络环境下是否仍工作？**
是。护栏纯本地运行（正则扫描 + 本地日志），不依赖任何外部网络；断网照常拦截与告警。

**Q8：审计日志 JSONL 单行损坏如何恢复？**
参考 SKILL.md「失败模式编码」表的"审计日志损坏"行：先备份，再删除损坏的那一行后重跑；或清空旧日志从当前写入重新开始。护栏对单行损坏容忍，不会因一行坏数据整体崩溃。

**Q9：同一条高危在闸一 deny 后，闸二复用闸还会拦吗？**
会。三道闸相互独立：闸一拦"写入"、闸二拦"复用"、闸三告警"趋势"。写入被拦不等于该技能安全，复用前仍须过血缘闸（尤其当内容被强行改写到别处绕过写入闸时）。

**Q10：`guard:allow:all` 为什么被代码拒绝？**
若允许 `all`，内容可自携开关解除整条闸一，等于把护栏的"防不自知"前提连根拔起。代码对 `allow:all` 直接拒绝，只接受精确 `rule_id`，从机制上堵死自毁路径。

**Q11：漂移自查的"绝对数门槛"是什么？**
除不安全率比例外，大库还需同时达到绝对命中数门槛才告警（避免"1 篇命中 / 总数 500"这种噪声触发）。具体门槛见 `drift_report.py` 输出与 `audit-report-v2.md`。

**Q12：能否把护栏接进 GitHub Actions 做 PR 卡点？**
能。在 CI 中于写入 / 合并前运行 `python scripts/redflags.py <changed-files>`，非 0 退出即阻断合并；配合 `--json` 输出可把命中项渲染进 PR 评论。这等价于把"闸一"搬到云端 CI。
